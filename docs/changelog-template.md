# 软件更新日志模板

在管理后台「更新日志」选择软件，按以下结构填写并保存草稿。关联反馈后，默认带入提出者的账号名称；发布前可填写其公开昵称或选择匿名。没有内容的分类与升级说明自动省略。

```markdown
# 软件名称 更新日志

## [1.2.0] — 2026-11-04

这次更新让导出更稳定，也让常用功能更容易找到。

### 新增

- **支持批量导出**：一次选择多份记录，统一导出。
  感谢 小樱 提出反馈。

### 改进

- **记住上次的筛选条件**：返回列表后可以继续之前的工作。
  感谢 小林、小陈 提出反馈。

### 修复

- **修复导出时偶发的闪退**：包含较多图片的记录也可以正常导出。
  感谢 匿名用户 提出反馈。

### 升级说明

升级后首次打开会更新本地索引，请等待处理完成。
```

填写规则：

- 版本号对应宿主软件实际发布版本；日期填写发布日期。版本号在同一软件内唯一。
- 摘要说明本次更新给用户带来的变化；每条更新使用「分类 + 标题 + 变化说明」，以用户能观察到的效果描述，避免只写提交编号或内部术语。
- 同一条更新可以关联多条反馈。署名按条目去重，匿名显示“匿名用户”；没有关联反馈的条目也能发布。
- 公开昵称属于这份日志的快照。账号改名、停用或原反馈彻底删除后，已经保存的署名不会随之变化；需要调整时先取消发布，再编辑并重新发布。
- 保存草稿后先检查「展示预览」，再点击「发布更新日志」。已发布条目需要先取消发布才能修改。发布日志不等于解决反馈，也不触发软件部署、AI 整理或 Kaneo 同步。
- 内容按普通文字保存，展示页和 Markdown 会转义 HTML 与标记。不要在字段中填写需要执行的 HTML 或 Markdown。

宿主展示方式与 HTTP 接口见 [接入指南](integration.md#软件更新日志与反馈致谢) 和 [HTTP 契约](api.md#软件更新日志)。Feedback 自身的版本记录仍由根 `CHANGELOG.md` 和现有发布流程维护。
