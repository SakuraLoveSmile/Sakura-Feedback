- 内容：服务端 AI 客户端补齐 OpenCode 网关要求的请求头（`860a302`）。根因为 `chat()` 只发 `authorization` / `content-type`，而 OpenCode Console/Go 要求每次会话带稳定 `x-opencode-session`，缺失时直接 `400 MissingSessionID`（"Request is missing x-opencode-session ..."）。版本统一为 0.9.2，schema 保持 15，公共接口与配置无变化。

## 修复与本地验证（2026-11-17）

- 复现：真实网关 `https://opencode.ai/inference/go/openai/v1/chat/completions` 不带该头 → `400 MissingSessionID`；带 `x-opencode-session: ses_…` → `401 Invalid credential`（已过路由层，仅剩密钥校验），证明头是该 400 的唯一缺口。
- 实现：`apps/server/src/services/ai.ts` 的 `chat()` 统一携带 `x-opencode-session: ses_<sha256(模型+请求体) 前 32 位>` 与 `user-agent: feedback-ai/1.0`；会话 ID 由内容派生，同一会话重试复用同一 ID，不同会话互不相同，只发摘要不外泄原文；其它 OpenAI 兼容端点忽略该头，不按域名分支。
- 契约用例：`apps/server/test/external-clients.test.ts` 新增「携带 OpenCode 会话标识与自有 UA」，断言 ID 格式、重试同 ID、跨会话不同 ID 与 UA。
- 端到端：改后的 `createAiClient` 直连 OpenCode Go 端点（假 key）时 `test()` / `testVision()` 均返回「AI 密钥无效」而非原 400。
- 本地门禁：`pnpm build` / `typecheck` / `lint` / `test` 通过（server 33 文件 469 项、Web 39 文件 686 项）；`tools/release-notes.py v0.9.2` 与 `e2e/check-release-notes.py` 通过。
